工程闭环已成型 alpha 质量是主瓶颈 BTC 候选未过 gate paper queue locked live frozen

总判断

这个系统的工程闭环已经明显超过普通个人量化项目，短板不再是“能不能跑”，而是“研究产出的 alpha 是否足够硬，以及证据链是否足够统一”。现在应该停止扩更多 live/paper 外壳和策略数量，把重心切到 alpha 质量、回测证据一致性、候选门禁收敛。

架构结论：平台底座已经够用了。下一阶段最值钱的工作不是再造模块，而是把研究噪声压下去，让一个 BTC alpha 真的经得起 ledger、成本、regime 和 walk-forward。

主要风险

  1. 研究证据存在多套入口：strict evidence、fresh event-ledger rerun、closure run 的指标有差异，需要统一 canonical report。
  2. live/paper 代码非常多，安全壳强，但复杂度已经偏高。不要继续扩 live 模块。
  3. 当前策略数量不少，但真正接近 gate 的 alpha 很少。
  4. BTC alpha 的 PF margin 太薄，成本、切片、regime 一压就没了。
  5. 当前 worktree 还有一批既有 dirty files，应先清理分支状态，否则后续归因会变差。

下一步方向

1. Evidence Consolidation

  • 统一 baseline 口径：同一数据版本、同一 event-ledger、同一 cost model、同一 manifest。
  • 所有报告只认一个 canonical artifact。
  • 把 signal equity 彻底降级为 diagnostic，不参与 gate。
  • 目标：任何策略结果都能一条命令复现。

2. BTC Alpha Research 进入归因优先

  • 不再新增策略名。
  • 针对 perp_dual_trend 做交易级 attribution：哪些入场条件赚钱，哪些 exit 亏钱。
  • order-flow 改成 sizing/veto 因子，而不是 entry trigger。
  • 重点研究趋势延续低频持仓、liquidation shock 后的顺趋势恢复、compression 到 expansion 的突破确认。
  • 目标不是 Sharpe，而是先把 event-ledger PF 稳定推到 1.15 以上。

3. Gate 和 Paper 严格保持冻结

  • 当前没有策略进入 candidate_passed_internal_gate。
  • 不创建 paper queue。
  • live 继续 frozen。
  • 只有当 1-3 个候选同时过 PF、WF、regime、cost stress、PBO/DSR、no-lookahead、ledger gate，才进入 paper_review_pending。

4. 系统复杂度收敛

  • live/paper/G5-G9 模块很多，下一阶段不要继续扩展。
  • 做一次 runtime boundary audit：哪些是真入口，哪些只是 review-only。
  • 前端只服务诊断，不做更多花哨页面。
  • CI 固化最小核心测试集：data quality、event-ledger、no-lookahead、promotion gate、paper/live no-side-effect。

建议下一个 Sprint

名称：BTC Alpha Attribution and Evidence Unification Sprint

验收目标

  • 统一 BTC canonical backtest report。
  • 输出 per-trade attribution report。
  • 明确 3 个盈利/亏损 regime。
  • 只改 1 个主候选：btc_perp_dual_trend_v3。
  • PF 目标 >= 1.15，turnover <= 1000%，WF >= 80%，regime >= 75%。
  • 若未达标，继续保持 research_failed / candidate_gate_failed。
执行边界：不打开 paper，不打开 live，不降低 gate，不新增一堆策略，不绕过 event-ledger。
