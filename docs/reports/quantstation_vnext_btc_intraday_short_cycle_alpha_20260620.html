8. 下一张工程票

任务：为 pullback_reclaim_24_dd100_4htrend100_v1 建 research-only event ledger backtest。 目标不是提高收益，而是确认这条 alpha 是否经得起账本、成本、滑点、时间分段和市场状态的审计。
  • 定义事件对象：entry timestamp、trigger state、context state、label horizon、禁止使用未来函数。
  • 生成模拟 OrderIntent，但不接 broker，不进入 paper runtime。
  • 所有 PnL 从 fill ledger 推导，不能直接从 bar return 记账。
  • 记录 experiment manifest：data_version、strategy_version、params、cost_model、slippage_model、commit_hash。
  • 做 cost stress：至少覆盖 10 bps 基准、加倍 taker 成本、保守滑点、错过成交和延迟进入。
  • 做 walk-forward 和 regime 分段：要求确认不是单一时期或少数尾部事件驱动。
  • 输出 promotion gate 报告，只允许给出“继续研究 / 拒绝 / 回到事件定义”的结论。

11. 结论

可以继续，但只能沿研究管线继续。 BTC 日内方向已经从“是否有剥头皮策略”推进到“是否存在可审计的日内短周期 alpha”。目前唯一值得推进的是 pullback_reclaim_24_dd100_4htrend100_v1 的事件账本回测。除非该回测通过成本压力、walk-forward、regime 和尾部依赖审计，否则不得进入候选策略、paper 或 live。
