# 研究候选到运行候选：人工交接设计

日期：2026-09-24。基线：`209507ea74121e07337f838705d60533e93b5848`。

本文前半部保留该基线的前端交付记录。后续另票的后端源码候选见下方“2026-09-24 后端候选实现”，不代表已经合入或启用。

## 交付边界

本轮实现前端交接准备与接收交互，复用 Alpha 工厂、Qlib 运行概览和 BTC 原控制台。既有后端提供研究读取与已注册策略启动，不提供研究模型包的审批、账户绑定和注册事务；本轮不臆造这些 API，不改变后端或执行合同。按钮禁用不是部署功能已贯通的证明。

| 阶段 | 本轮能力 | 权威与限制 |
| --- | --- | --- |
| 选择来源 | 工厂候选逐条入口；Qlib 精确运行入口 | 不选 latest，不选择相似候选；工厂只能引用最终审计 run，不拿训练折模型冒充冠军 |
| 核对交付包 | 展示候选、策略、源码、数据、市场、周期、封印引用与缺项 | 封印证明文件完整性，不证明策略有效；研究配置不等于运行规则审定 |
| 填写意向 | 离线验证或明确 BTC 来源的 OKX Demo 意向；交接说明 | 账户显示未绑定，不读取账户，不允许手填账号／哈希充当授权；不修改参数、仓位和成本 |
| 人工确认 | 确认已理解边界，保存当前标签页草稿、下载 JSON | `local_draft`，不是审批、发布或可执行包；所有安全旗标为 false |
| 接收交接 | 同标签页进入原 BTC 控制台，重新读取研究来源并比较完整投影 | 变化、错配、损坏、丢失、迟到结果均不改绑；不改已有策略选择，不调用 operator controller |
| 服务端审定／注册 | **未接通**，明确列出依赖且发布按钮恒禁用 | 不能写 approved/registered，不登记 runtime candidate，不启动 Demo/paper/live |

## 交互与页面归属

1. 在 Alpha 工厂候选卡或 Qlib 概览点击“准备部署交接”，就地展开三步面板。关闭不会更改研究结果。
2. 第一步显示交付包清单：模型、特征与预处理、校准及单位/期限、仓位、退出、成本与事件时间、运行包及审批回执。只从已知后端字段提取信息，不把空值补成通过。
3. 第二步填写拟交接环境与非敏感说明；真实账户目录和绑定尚缺，始终显示“未绑定”。多市场来源可以导出研究交接清单，但不能送进 BTC 控制台。
4. 第三步需显式勾选边界确认，才能保存/导出。可以为 rejected 候选导出问题清单，但绝不改变原研究结论。
5. BTC 控制台只增加独立的交接卡；没有 `researchHandoff` 查询参数时不读取草稿、不请求研究数据，也不显示新卡。原控制台、底部工作区、目录和受控启动确认保持原样。

## 本地草稿合同（不是共享执行合同）

`research_candidate_handoff_draft_v1` 仅是浏览器用户资料：UUID、创建时间、研究来源白名单投影、投影比对字符串、拟交接环境、说明和边界确认。`account_binding=not_bound`、`status=local_draft`。

仅保存到 `sessionStorage` 的 `qs.research-handoff.v1.<uuid>`；同标签页刷新保留，跨浏览器/关闭标签页不保证保留。URL 只携带 UUID，不携带账号、模型路径或权限。存储拒绝/配额错误必须显式报告，可改为下载清单。下载对象不包含模型权重、行情大文件、原始 payload、物理根目录或账户事实。

比对字符串不是密码学证明；存储与 URL 均不可信。接收页必须按草稿指向的精确 run 再次 GET 已有后端研究接口，通过封印状态、身份与安全合同检查，再比较投影。即使重新匹配，也只说明研究引用相同，不说明服务端已经批准。任何本地伪造的批准、账户或运行状态都不得传给控制器。

Qlib 的旧只读合同有七个必备 false 旗标，其他已返回的旗标必须也是 false；工厂现有十个 false 旗标必须齐全。不得为兼容直接把缺失的必备字段当作 false。

## 后续真正注册所需的服务端边界（原前端阶段设计）

由独立的共享候选交付服务负责，而不是策略、Qlib trainer 或浏览器负责：

- 不可变策略包：最终模型文件、特征/预处理、校准与输出类型/单位/期限、仓位/退出政策、成本/时间/精度、状态版本、数据/代码/参数及内容摘要。
- 审定回执：绑定精确包 digest、来源 run/candidate、目标领域和执行适配合同；可证明拒绝、到期、撤销和版本不兼容，不接受客户端 approved 布尔值。
- 账户绑定：服务端返回不含秘密的可用账户标识和范围，经授权绑定；研究页面不读取 private API 或密钥。
- 注册事务：用幂等键和乐观版本检查将“已审定包＋目标账户＋执行适配版本”登记到候选管理目录；并发和未知结果先查登记回执，不盲重试。现有运行入口尚未消费此目录，管理登记不代表可启动，也不携带交易权限。
- 策略包 v2 显式声明结算币种；账户币种必须与之精确匹配。绑定、审定、登记和精确解析时均重新校验，币种变化使旧审定失效。v1 包不自动升级或默认补币种，必须重新验证与审定。
- 启动仍复用原 BTC 控制台人工确认与后端预检；Risk/Guardian/OMS/保护/账本保持执行权威。权限和实时账户事实过期时仍拒绝。
- 对外读模型应返回草稿、待审、拒绝、审定、登记、撤销的明确状态与证据，不用前端猜测或用“文件存在”推导权限。

这些会改变共享交付与执行绑定合同，须单独限定票据和独审，不能在本次前端发布中顺带实现。

## 验收与停止条件

- 真实来源可展开、填写、确认、保存、下载并在原控制台重新核对。
- 错 run、重复候选、seal 不匹配、unsafe/missing flags、sessionStorage 注入、其他市场、草稿缺失/损坏、返回晚于导航等保持拒绝。
- 本地草稿不产生 POST、不改已注册目录、不触发训练、恢复、账户读取或控制请求。
- 旧控制台/只读禁用/公共行情兼容，TypeScript 和构建通过；独立审查后只在 canonical main 的 3000 页面验收。
- 达标后交付这一次前端工程。未实现的服务端审定注册如实保留，不循环加模型、调策略或扩执行链。发布不等于“研究到交易”已全部完成。

发布风险：`research_readonly_release`；不包含 `quant_crypto`、共享执行 schema、权限或后端变更。保留基线为回退依据；不覆盖历史研究、离线账本或暂停运行。
