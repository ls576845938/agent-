# Financial ML Validation Rules

来源主线：Advances in Financial Machine Learning。

## 适用范围

特征工程、标签生成、机器学习模型、参数搜索、策略验证、promotion gate。

## 核心规则

1. 金融样本通常不是 IID；不能直接照搬普通随机 K-fold。
2. 标签窗口重叠时，交叉验证必须 purge 重叠样本，并设置 embargo。
3. 特征标准化、分位数、波动率、相关性、协方差只能用训练期或历史滚动窗口估计。
4. 未来收益只能作为标签，不能泄漏进特征。
5. 参数搜索次数、失败试验、被丢弃策略都必须记录；否则无法评估数据挖掘风险。
6. 策略评价必须拆分 signal quality、position quality、execution quality。
7. 如果使用 ML，必须记录标签定义、样本权重、训练窗口、测试窗口、embargo 规则、特征重要性。
8. Meta-labeling 只能作为过滤或 sizing 层，不能掩盖 primary signal 的经济逻辑缺失。
9. Triple barrier 标签必须记录 profit-taking、stop-loss、vertical barrier 和价格可见时点。
10. 任何模型进入 paper 前，必须通过无未来函数测试、样本外测试、成本压力测试和参数稳定性测试。

## 验证门槛

最低 evidence pack：

- 数据范围和数据版本。
- 策略假设和经济解释。
- 训练、验证、测试切分。
- 是否使用 walk-forward、purged CV 或 CPCV。
- 成本和滑点压力：至少包含基础、偏保守、极端三档。
- 参数邻域稳定性，而不是单点最优。
- 年份/市场状态分段结果。
- 最大正贡献年份占比，防止单一年份支撑全部收益。
- 换手、持仓天数、暴露比例、容量估计。
- 所有试验次数和被拒绝配置数量。

## Codex 开发检查

修改研究代码时必须问：

- 这个特征在交易决策时真的可见吗？
- 标签窗口是否和训练样本重叠？
- CV 是否 purge 和 embargo？
- 参数是否在测试集上被反复调过？
- 回测报告是否记录了失败试验？
- 净值曲线是否能由逐日/逐笔 ledger 复原？

## 禁止模式

- 全样本标准化后再切训练/测试。
- 先看全样本最优参数，再声明它是固定策略。
- 只报告最优策略，不报告候选池规模。
- 用 accuracy 评价极度不平衡的交易标签。
- 把模型概率直接当仓位，不经过风险预算和容量约束。
